Title: Mesh._get_coords_for_basis: DMCreateInterpolation fails ('New nonzero caused a malloc') on some ranks for particular partitions; other ranks crash in the next collective

## Summary

`Mesh._get_coords_for_basis(degree, continuous)` calls `dmold.createInterpolation(dmnew)` (coordinate DM → basis DM). On particular partitions of a small 3-D tetrahedral mesh, this fails **on some ranks only** with PETSc error 63:

```
[5]PETSC ERROR: Argument out of range
[5]PETSC ERROR: New nonzero at (0,3) caused a malloc. Use MatSetOption(A, MAT_NEW_NONZERO_ALLOCATION_ERR, PETSC_FALSE) to turn off this check
[7]PETSC ERROR: New nonzero at (6,51) caused a malloc ...
[5]PETSC ERROR: Inserting a new nonzero at global row/column (66, 96) into matrix
```

The ranks that fail raise. The others continue into the next collective, and the job dies with
`Fatal error in internal_Allreduce_c: Message truncated` (rank-asymmetric failure, the #842 class).

## Reproduction

```python
import underworld3 as uw
mesh = <load the 3-D mesh>                 # 425 tets, gmsh OCC, see below
c = mesh._get_coords_for_basis(1, True)    # degree 2 fails the same way
```

| mesh | ranks | result |
|---|---|---|
| 425-tet notch-block mesh | 4, 8, 12, 14 | OK |
| 425-tet notch-block mesh | 16 | fails on ranks 5, 7, 9, 14, 15, every run |
| 1052-tet mesh, same geometry | 16 | OK |
| 230-tet extruded-notch mesh (about 15 cells per rank) | 16 | OK |
| 4447-tet mesh, same geometry | 16 | OK |

So it is not simply "too few cells per rank". A particular partition trips the interpolation's preallocation. The mesh is gmsh OCC: a box, a lower-layer box, and an extruded block fragmented into conforming volumes (`notch_length_scale/drivers/make_notch_block_3d.py 4.8 32 2.5 - --near 1.2 --coarsen 4` in uw3-campaigns). The reproducer is `drivers/repro_coords_basis.py` there.

## Expected

Coordinates at the basis nodes on every rank. Or, if a partition is unsupported, an error raised **collectively**, so it cannot hang or crash the other ranks.

## Notes

- For P1 continuous on straight simplices the basis nodes are the vertices, so no interpolation matrix is needed. Higher degrees could be computed per cell from the reference nodes, without `createInterpolation`.
- At minimum the failure should be made collective (an allreduce of an error flag before the next collective), so one bad rank does not corrupt the others' MPI state.
