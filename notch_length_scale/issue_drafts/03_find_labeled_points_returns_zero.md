Title: petsc_dm_find_labeled_points_local returns [0] for a missing label; refinement callbacks then move vertex 0

## Summary

`petsc_dm_find_labeled_points_local(dm, label_name)` returns `np.array([0])` when the label is not present on the DM (`cython/petsc_discretisation.pyx`, around line 205):

```python
label = dm.getLabel(label_name)
if not label:
        uw.pprint(f"Label {label_name} is not present on the dm")
        return np.array([0])
```

The callers use the result as a list of vertex indices. The spherical, annulus, geographic and segmented refinement callbacks scale those vertices onto a radius. So a missing label silently moves **vertex 0** instead of moving nothing. The message goes through `uw.pprint` (rank 0 only), but the condition is rank-local: a rank whose DM lacks the label prints nothing.

## Suggested fix

Return an empty integer array (`np.array([], dtype=int)`), and if needed warn from the rank that hits it (or collectively). Callers then naturally do nothing.

Found while checking label-driven refinement callbacks in parallel. The library shell callbacks themselves were verified consistent at np 4: Annulus and SphericalShell at refinement 2 show zero ghost/owner coordinate mismatch and exact radii. This return value is the remaining hazard.
