Title: custom-P FMG prints a false PETSc error ('Must call KSPSetUp() ... before PCFieldSplitGetSubKSP') on every Stokes solve

## Summary

Every Stokes solve that uses custom-P FMG (`set_custom_fmg`, or a mesh-owned tail) prints a PETSc error block like this, although the solve then proceeds normally:

```
[0]PETSC ERROR: Object is in wrong state
[0]PETSC ERROR: Must call KSPSetUp() or PCSetUp() before calling PCFieldSplitGetSubKSP()
[0]PETSC ERROR: WARNING! There are unused option(s) set! ...
```

It comes from probing the fieldsplit sub-KSP before the PC is set up, in custom_mg's installed-PCMG check: `outer.getFieldSplitSubKSP()` around `custom_mg.py:2225` on development. The exception is caught, but PETSc has already printed.

## Why it matters

The block lands in exactly the place where a real failure prints. Diagnosing a genuine custom-MG failure (orphan transfers, NaN norms) meant reading past this false error every time. It also trains readers of the logs to ignore PETSc errors.

## Suggested fix

Check the PC's setup state before asking for the sub-KSPs (or set it up first). Alternatively, push a PETSc error handler that suppresses printing around this probe.
