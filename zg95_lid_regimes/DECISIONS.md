# Decisions ledger: the zg95 fault and rollback drivers

These drivers (`drivers/annulus_faults.py`, `annulus_fault.py`, `box_fault.py`, `annulus_model.py`)
are campaign code in `uw3-campaigns`, not part of underworld3. Every choice they make that the
library does not make for them is a campaign decision and is recorded here, dated, with the
evidence and who ruled. The hub's day-to-day record is `HUB.md` at the repository root; the
pages linked there hold the figures. A run's own `README.md` carries a "Choices" block
(every knob below, its value, set or default) and `run_info.json` the resolved parameters,
since 094e4f3. Louis, 2026-11-01: "every exposed knob is a recorded choice"; 2026-11-02:
these decisions must be findable by other Claudes and by people, not only by the hub.

Newest first within each section. "Ruled" means Louis decided; "measured" means the value
rests on a kaiju measurement cited; "taken" means a default inherited without a decision.

## Fault placement and geometry

| knob | value | status | evidence / ruling |
|---|---|---|---|
| **the fault's discretisation (principle)** | the ladder's rungs are the fault's own points; the band width is the local mesh size along the fault (an average where the mesh is not uniform); neither is a knob | ruled 2026-11-03 (Louis, clarifying decision 1b): "the along-fault resolution is set by the discretisation of the fault, the fault width is set by the local mesh size (which may not be uniform everywhere that the fault is embedded, but an average of some sort seems sensible here). What is going wrong in our model is that we are also defining the fault and its discretisation as a knob we can control. Generally this is not true - the ladder is built from the fault points and we can see if that is sufficient or not, but we generally can't just change it." | **Ruled 2026-11-03 (Louis, on kaiju's design page UANqhA82AfRoh7fjgrPwYG): "This is a lot of design for what is, actually, a simple driver to test a concept. If we implement this, then we should consider it part of a plate-boundaries module. I'd say - make the ladder equant if given the choice. The half-width is one cell (I think) and so the discretisation along the length would be similar."** So the ladder is EQUANT: rungs at the local cell size h, band width 2h (half-width one cell), which is recipe v2 as accepted (uw_spacing 0 = one base cell; W = 2S = 2h). The driver keeps that; the division actually used is stated in the record. **And on the width, Louis 2026-11-04, correcting the design page's "unmeasured": "we looked at whether to cut the band in the centre using the original nodes of the fault and found that this was best. Otherwise the cell cuts are another calculation to make rather than just having the fault use its own nodes. One cell either side of that gives a good mesh and there is no benefit to having more cells in the fault itself. Long time ago but we did look at this as part of the ladder evaluation (cf. non-ladder cuts)." So the cut on the fault's own nodes with one cell either side (W = 2h) is the measured choice from the ladder evaluation; a one-cell band is withdrawn as a candidate and more cells buy nothing. Citation (notes session, 2026-11-04): underworld3 issue #595 (2026-08-17, open), the cut-in-band configuration with Louis live: an isolated fault at isotropic contrast 1e-3; the default band cut along its centre-line snapped a rail vertex onto the cut (min angle 32.2 -> 13.0 deg, zone 104 -> 144 cells, mid-fault slip 0.4290), while a band meshed three nodes across (two rails and the centre-line row, one cell either side, the cut sampled at the spine's own vertices) snapped nothing (28.8 -> 28.8 deg, 132 -> 132 cells, slip 0.4315, no-opening leak 5.6e-17); no snap parameter prevents the defect. That covers the cut on the fault's own nodes and one cell either side giving a good mesh; "no benefit to more cells" was not measured as a cells-across comparison (the nearest: the uncut band at w/4 gave 0.428-0.433 against the three-across cut band's 0.4315) and stands as Louis's recollection. The journal's 2026-10-13 entry ("the two embeddings") describes the split consuming the spine's vertices but carries no measurement.** Kaiju's full design (division at h(s), W = BAND_CELLS x mean h, division record, no knob; draft f393fd7 on kaiju/fault-division-draft, offline-placed on all 80 stored faults, not run) is shelved as the design input for a library plate-boundaries module, with the dev hub. |
