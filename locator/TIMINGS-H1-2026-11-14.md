# Locator branch 51e8973f against development bc3d5362: near-vertex timings

*Measured by H1 (the parallel review desk) on a 96-thread Linux workstation (Intel Xeon Gold 6240R,
AVX-512; MPICH); placed here by the dev hub from H1's message for H4's PR body (rule 9 clean).*

- **Load:** the machine's load average was 21 to 24 from other jobs, so single timings carry about +/-15 % noise.
- **Method:** the same as H1's #1117 review. A simplex box, h = 1/12 in 3-D and 1/32 in 2-D, with a P2
  field; each rank queries N/np points spread over the whole box, so in parallel most are foreign to it;
  each figure is the best of 3, with fresh jitter each time and the maximum over ranks; "near-vertex" means
  within 1e-6 of a mesh vertex. Each row is development -> branch.

- **Near-vertex points:** the branch is faster everywhere; 3-D `global_evaluate` at np 4 goes from 22.3 to
  7.8 s, reversing the cost #1117 added (3.2x there).
- **One regression, reproduced in 3 runs: serial, mostly exterior points.** `evaluate` +50 to 65 % and
  `global_evaluate` +35 to 55 %, although `_robust_owning_cells` itself is faster; so the extra cost is in
  the evaluation path for points outside the domain, not in the walk. At np 4 the same set is faster.
- **Not timed:** the lazy locator build after a geometry change (H2's mover check covers that), Open MPI,
  quadrilateral or hexahedral meshes.
